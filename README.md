# 船舶换代理期间的港口服务单领取与交接

港区入口在 `/west`。下载通过浏览器中可用的详情页链接触发。明细为 UTF-8 CSV，首行是列名。 `split` 留空或由以竖线分开的 `起-止:金额` 组成。所有业务时间为本次演练日内整数，服务和授权均以含起不含止计。详情和文件中的批次、识别号以及修订须能互证。港区的“续页”链接到下一页，该页是否已看到由当前门户应答确认。门户允许从同一港区入口重新打开。
 
`data/agencies.json` 是管理公司提供的班次授权和请款对象。每条授权限定项目、代理、港区、靠泊批次与时间范围。重叠且无法从同一代理的正式替代号解除冲突时，由管理公司核对。项目在领用时只能核对自身可见单据和证明其可见行所属的来源引用，含其它项目明细的原件须经管理公司查看。

## 本地来源

资料均为合成记录。Node.js 22 环境下执行 `npm ci`，再用 `npm run sources` 启动，默认监听 `127.0.0.1:4180`。可用环境变量 `PORT` 修改端口。在容器中运行时，服务和访问端处于同一网络命名空间。

`data/sources.json` 保存原始报文及站点页面。连续响应由来源按同一进程内的观察次数提供。阶段从 `initial` 启动，本地演练人员可用 `POST /scenario/阶段名` 切换，未覆盖的路由延用初始响应。切换不清空来源的请求记录。重开服务会复位。

执行 `npm test` 核对来源契约。本机浏览器依赖由 Playwright 1.56.1 提供，可在首次准备时执行 `npx playwright install chromium`。容器方式可先执行 `docker build -t port-services-sources .`，再执行 `docker run --rm port-services-sources`。镜像准备完成后的验证不需要外网。

## 项目交付回执

财务收件台 `/finance/项目号/receipts` 是独立来源。请求 `POST /finance/项目号/claims` 带上 `claimId`、`document`、`revision`、`line`、`segment` 和 `amount`。单行分段时，以原单、修订、行号和半开时间段定位对应原始明细。受理的行会出现在回执，提交响应仅表示队列收到。冲回请求 `POST /finance/项目号/reverse` 指明 `claimId`。只有 `reversed` 的回执确认金额已经从该项目当前账上冲回。

## 收件与交接应用（`src/`）

应用只用 Node.js 内置能力与已锁定的 Playwright，状态集中在一个原子写入的 JSON 文件，门户换页、重登或进程重启后凭它接着收、接着发。命令行：

```bash
npm run app -- collect   --url http://127.0.0.1:4180 --state work/state.json --downloads work/downloads
npm run app -- send      [--claims 编号,编号]   # 缺省发送全部 prepared 请款
npm run app -- reconcile                          # 拉取各项目回执对账
npm run app -- reverse   --claim <claimId>       # 按原编号请财务确认冲回
npm run app -- view      [--project 项目号]       # 缺省为管理公司全量视角
npm run app -- impact    --document SV-19 --revision 1
```

关键规则的落点：

- **按识别号与批次取证，不按船名**：浏览器只从港区入口进入详情页；下载后用详情页的原单号、船舶识别号、靠泊批次、修订与 CSV 每行互证。文件名或内容对不上时核验不通过，差异与重取入口（详情页、下载地址、SHA-256、落盘路径）全部留痕，错误内容不产生任何明细；再次 `collect` 即重取。同一“文件已生成”地址的多次下载按字节哈希分别留档，对应不同批次不会被合并。
- **按服务时间与班次授权判定去向**：授权必须同时匹配代理、港区、靠泊批次与含起不含止时间窗。原单 `split` 给出分段依据时跨班拆给各项目；无分段依据的跨班整行、授权间隙、重叠授权只进追补清单（`followUps`），不猜拆。某港区未出齐（如续页 503）只标记 `areaReadiness` 未齐，不阻断其它已齐港区出材料。
- **错靠泊修订**：同原单号出现新修订时，旧修订明细整体标记被取代，旧项目视角立即不可再领用；未发出的旧请款直接 `stopped`，已在队列或已接收的保留原编号。新项目只能凭新批次自身授权取得明细，授权窗外的段落转追补，不会向无权限项目复制原件。
- **财务交接以明细行为单位**：`claimId` 为 `原单/修订/行号/半开时间段`，提交 202 只表示入队，真实接收以回执为准。晚于更正到达的回执仍计为真实接收并打 `late`，须按原编号冲回；只有回执变 `reversed` 才表示金额离开当前账。同一服务（`document:line:segment`）任何时刻最多存在一条当前待付，旧承诺未冲回时新请款在 `send` 处被阻断并注明回执号；`view` 可区分准备中、队列中、当前待付与等待冲回。
- **视角隔离**：管理公司视角含全部原单（含差异件）、追补与修订流水；项目视角只含本项目授权内明细，来源仅给证明本行的引用（案页、下载地址、文件名、哈希），含其它项目明细的原件不在项目侧展开。

`npm test` 共 18 个测试：来源契约、浏览器操作、CSV 与下载核验、授权/拆分/追补/修订领域规则，以及覆盖两个演练阶段的端到端流程。
